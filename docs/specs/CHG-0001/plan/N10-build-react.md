## Order

1. Pure modules (whitespace, returnTo, todoId, API types, userMessage) against `tests/unit`.
2. API client, SessionProvider, RequireAuth, app shell, routes, error boundary, not-found page, log in and sign up against `tests/component/auth` and `navigation`.
3. List screen with filter, search, pagination, row toggle, delete and clear-completed dialogs against `list` and `errors`.
4. To-do form (create, edit) and detail page against `todo-form`.
5. Styles from the design tokens, `index.html`, `vite.config.ts` (dev proxy), then axe component tests, typecheck, lint.
6. One `pnpm -C web e2e` run to see that only the missing API fails; attach the unit/component JUnit report as evidence.

## Risks

- F-26: `throwingResponse` is a 2xx with no Content-Type whose body read rejects; the client reads every 2xx JSON body regardless of Content-Type and maps a body-read rejection to `{ kind: 'unexpected' }` (a `fetch` rejection is `network`), so the N-2 tests pass within sdd §6.1.
- Focus and no-remount rules (filter change keeps the `<h1>` element and the radio focus; pagination moves focus to the `<h1>` at once) depend on never keying the list page by location.
- Native `<dialog>` under jsdom (a test-setup shim provides `showModal`); the dialog is mounted only while open.
- A 401 while signed in is reported to `SessionProvider` and the call site then shows no error of its own.
- e2e cannot go green in this worktree: `api/` holds only failing stubs until N09 merges. Firefox for Playwright may not be installed; it is reported, never installed.
- F-24 (version pins, ADR-0001): TypeScript stays on 6.0.3 because the pinned `typescript-eslint` 8.72.1 declares the peer range `typescript >=4.8.4 <6.1.0`, which excludes TypeScript 7. The test-only dev dependencies beyond the ADR-0001 list are jsdom (Vitest DOM environment), `@testing-library/jest-dom` (matchers), `@vitejs/plugin-react` (JSX transform for Vite and Vitest), `eslint`, `@eslint/js` and `typescript-eslint` (the `lint` script) and `@types/node` (Node types for the e2e support code); they were added by the tests node (N08), not by this node, and are test or tooling only.

- `.harness/changes/CHG-0001/evidence/test-report/N10-build-react.unit-junit.xml`: the attached Vitest report (written by `harness evidence attach`).
- Choices inside the spec that a reviewer may question:
  - `AppErrorBoundary` also remembers a caught error outside the render (module variable, cleared on pathname change or unmount). React renders a tree that threw a second time before committing, and discards the boundary state if that retry does not throw; without this the test `errors.test.tsx` "following the error page's link to home" (a component that throws only once) never shows the error page. The spec rule "only a pathname change clears it" is kept.
  - The list screen starts its request in a layout effect and renders the response with `flushSync`, so the rows are on screen in the task that receives the data; the tests read the rows straight after the heading appears.
  - The list screen, when it is the page the document loaded on, leaves focus at the start of the document (the skip link must be the first Tab stop, `a11y.test.tsx` NFR-001 AC-2); every other screen focuses its heading on arrival.
  - A signed-in visitor on `/login` is sent on by `PublicRoute` to the valid `returnTo` or `/todos`, which is also how a successful log in navigates (router navigation only).
- Two component tests fail and are left unchanged (see the report to the orchestrator): `web/tests/component/todo-form.test.tsx` "REQ-TODO-002 AC-7 the due date shows as the same calendar date under TZ=Pacific/Kiritimati" and "...Pago_Pago". No rendering that also satisfies `list.test.tsx` REQ-TODO-003 AC-1 (a completed row shows its due date) can give exactly one match.
